# 逻辑谬误标注清单(Fallacy Checklist)

## 标注格式

每条标注四要素:

```
【段落定位】第 X 节第 Y 段(引原文起始句)
【谬误类型】<类型名>
【为什么成立】<论证链条哪里断了,一句话说清>
【改写建议】<这段该怎么写才站得住>
```

只标注确定成立的。疑似但拿不准的放进输出末尾"存疑区",写明怀疑点,不强行定罪。统计各类型出现次数,在报告开头给分布。

## 一、论证结构类

| 类型 | 判定要点 |
| --- | --- |
| 循环论证 | 结论藏在前提里,论证绕一圈回到出发点 |
| 稻草人 | 把对方观点改写成更弱的版本再攻击 |
| 虚假两难 | 只给两个选项,无视中间地带与第三选项 |
| 滑坡论证 | 从 A 推到 B 再到 Z,中间每一步无独立证据 |
| 诉诸权威 | "某大佬/大厂支持"当作正确性证据;权威只增强先验,不替代论证 |
| 诉诸新潮 | "我们用深度学习/大模型"本身当作贡献 |
| 诉诸传统 | "一直是这么做"当作正确性证据 |

## 二、证据类

| 类型 | 判定要点 |
| --- | --- |
| 以偏概全 | 少量样本/单一数据集推出普遍结论 |
| 幸存者偏差 | 只统计"活下来的"样本(如只回访成功案例) |
| 挑选证据 | 只报支持结论的实验,不利结果不提 |
| 轶事证据 | 用个案故事替代统计证据 |
| 样本污染 | 训练集与测试集重叠、数据泄露后仍报性能 |

## 三、统计类

| 类型 | 判定要点 |
| --- | --- |
| 相关当因果 | "A 与 B 相关"直接写成"A 导致 B",无机制/干预/时序证据 |
| 因果倒置 | 方向写反(B 导致 A 写成 A 导致 B) |
| p-hacking | 反复换检验/切数据直到 p<0.05 才停手 |
| 多重比较未校正 | 跑 N 组检验不校正(如 Bonferroni),按 0.05 报显著 |
| 忽视效应量 | 只报 p 值不报效应量与置信区间 |
| 发表偏差 | 用"文献里都显著"作为证据,忽视抽屉里的阴性结果 |
| 回归均值误读 | 把极端值自然回落归因为干预效果 |

## 四、表述类

| 类型 | 判定要点 |
| --- | --- |
| 模糊定义 | 核心概念(如"智能""鲁棒")全文无操作定义 |
| 偷换概念 | 同一词在论证前后含义漂移 |
| 不当类比 | 类比对象的关键属性不同,类比不成立 |
| 不可证伪 | 结论无论出现什么证据都"对" |
| 诉诸无知 | "没人证明它错"当作"它对"的证据 |

## 执行要点

1. 先通读全文标记论证段落,再逐段对照清单,不要为凑清单硬找谬误。
2. 一段可以同时命中多个类型,分别标注。
3. 报告里"模型判断"与"原文引文"分开呈现,用户可自行复核。
4. 目标是让用户看清论证弱点,不是把论文批倒;改写建议与标注同等重要。
